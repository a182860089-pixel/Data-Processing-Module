# 异步轮询测试工具使用指南

## 📋 概述

异步轮询测试工具是一个可视化的测试平台，用于模拟和测试异步任务处理和轮询机制。它提供了完整的任务管理、进度跟踪、性能指标和实时可视化。

## 🎯 主要功能

### 1. 任务管理
- **批量创建任务**：支持创建 1-10 个并发测试任务
- **手动轮询**：可单独对任务进行手动轮询检查
- **任务重置**：随时可以重置或移除任务

### 2. 轮询控制
- **轮询间隔配置**：100ms - 5000ms，可自定义
- **模拟时长配置**：1s - 30s，模拟实际业务处理时间
- **自动/手动模式**：支持自动依次启动或全部同时启动

### 3. 性能指标
实时显示以下指标：
- 总轮询次数：所有轮询请求总数
- 成功轮询：成功获取状态的轮询次数
- 失败轮询：失败的轮询次数
- 平均轮询间隔：平均每次轮询耗时
- 总耗时：完成所有任务的总时间
- 活跃任务：当前进行中的任务数量

### 4. 任务可视化
- 实时进度条：带动画效果的进度显示
- 状态标记：pending/processing/completed/failed
- 详细信息：轮询次数、任务耗时等

### 5. 详细日志
实时显示每个任务的状态更新日志

## 🚀 快速开始

### 步骤 1：访问测试工具
在应用中点击 **🔄 异步轮询测试** 标签页

### 步骤 2：配置参数
在控制面板中设置：
- **轮询间隔**：决定多久检查一次任务状态
- **模拟时长**：模拟业务处理需要的时间
- **任务数量**：同时运行的任务个数
- **自动模式**：勾选以自动依次启动任务

### 步骤 3：启动测试
点击 **🚀 启动轮询测试** 按钮开始测试

### 步骤 4：监控进度
- 观察实时指标变化
- 查看每个任务的进度和状态
- 检查详细日志

### 步骤 5：停止/重置
- 点击 **⏹️ 停止所有轮询** 暂停所有任务
- 点击 **♻️ 重置** 移除单个任务

## 📊 工作流程

```
启动测试
  ↓
创建任务 (pending 状态)
  ↓
启动轮询 (processing 状态)
  ↓
定时检查进度 (每隔轮询间隔)
  ↓
进度更新 → 显示进度条
  ↓
进度 >= 100% → 任务完成 (completed 状态)
  ↓
清理资源
```

## 🔄 轮询机制说明

### 轮询流程
1. **启动**：将任务状态设置为 `processing`
2. **轮询**：按配置的间隔定时调用轮询函数
3. **进度计算**：根据已用时间计算进度百分比
4. **状态更新**：实时更新进度、轮询次数等信息
5. **完成判断**：进度 >= 100% 时标记为完成
6. **清理**：停止定时器，记录耗时

### 性能计算
- **进度**：`Math.min((已用时间 / 模拟时长) * 100, 100)`
- **平均轮询间隔**：`sum(所有轮询耗时) / 轮询次数`
- **总耗时**：`任务完成时间 - 任务启动时间`

## 💡 使用场景

### 场景 1：测试轮询频率影响
1. 设置不同的轮询间隔（如 100ms、500ms、1000ms）
2. 对比平均轮询间隔的变化
3. 观察性能指标的差异

### 场景 2：压力测试
1. 增加任务数量（如 5、10 个）
2. 同时运行多个任务
3. 监测系统响应情况

### 场景 3：超时处理
1. 设置较长的模拟时长（如 30s）
2. 观察任务是否正确完成
3. 验证超时机制

## 🎨 UI 组件说明

### AsyncPollingTest.vue
主要测试工具组件，包含：
- 控制面板：参数配置和操作按钮
- 指标面板：实时性能指标展示
- 任务列表：所有任务的状态和进度
- 日志区域：详细的操作日志

### useAsyncPolling.ts
核心 Composable，提供：
- `createTask(name)`：创建新任务
- `startPolling(task, pollFn, interval, timeout)`：启动轮询
- `stopPolling(taskId)`：停止单个轮询
- `stopAllPolling()`：停止所有轮询
- `resetMetrics()`：重置指标
- `cleanup()`：清理资源

## 📈 性能优化建议

1. **轮询间隔**
   - 过短：增加服务器压力
   - 过长：降低响应灵敏度
   - 建议：500ms - 2000ms

2. **任务数量**
   - 根据浏览器性能调整
   - 建议：3 - 10 个同时任务

3. **超时设置**
   - 应大于模拟时长
   - 建议：模拟时长 × 2

## 🐛 故障排查

### 任务一直处于 processing
- 检查轮询间隔是否过长
- 检查模拟时长是否过短
- 尝试手动轮询

### 进度条不更新
- 检查任务是否真的在运行
- 查看浏览器控制台是否有错误
- 尝试停止并重新启动

### 指标显示不准确
- 点击 **重置** 清除所有任务
- 使用 **停止所有轮询** 停止活动任务
- 重新开始新的测试

## 📝 高级用法

### 自定义轮询函数
使用 `useAsyncPolling` 的 `startPolling` 方法创建自定义轮询：

```typescript
import { useAsyncPolling } from '@/composables/useAsyncPolling'

const { createTask, startPolling } = useAsyncPolling()

const task = createTask('Custom Task')

// 自定义轮询函数，返回 0-100 的进度值
const customPollFn = async () => {
  const response = await fetch('/api/task/status')
  const data = await response.json()
  return data.progress // 0-100
}

// 启动轮询：每 500ms 检查一次，30s 超时
startPolling(task, customPollFn, 500, 30000)
```

## 🔗 集成指南

将异步轮询测试集成到实际项目中：

1. **导入 Composable**
```typescript
import { useAsyncPolling } from '@/composables/useAsyncPolling'
```

2. **创建和启动轮询**
```typescript
const { createTask, startPolling } = useAsyncPolling()
const task = createTask('My Task')
startPolling(task, myPollFunction, 1000, 30000)
```

3. **监听指标变化**
```typescript
const { metrics } = useAsyncPolling()
watch(() => metrics.value.totalPolls, (newVal) => {
  console.log(`Total polls: ${newVal}`)
})
```
